架构图生成方案选择

先锁定“用 GPT 生成架构图”的落地形态。点击你倾向的方案，或者直接在终端里说明偏好。

A. Prompt 包
总体架构文档 + 模块摘要
↓ GPT 提示词
Mermaid / PlantUML 代码

手工 Prompt 包

整理一组可复制给 GPT 的提示词，让 GPT 生成 Mermaid 架构图。最快，适合先出图，但维护性一般。

B. 文档化图源
docs/architecture/diagrams/prompts
↓ GPT 生成 / 人工校订
docs/architecture/diagrams/*.mmd
↓ 嵌入总架构与模块文档
README / 总体架构 / 模块文档

Prompt + Mermaid 图源入库

把提示词、图源和嵌入位置标准化。适合当前文档型项目，可复用、可审查、不会引入 API 自动化复杂度。

C. 自动生成流水线
文档扫描脚本
↓ OpenAI API
Mermaid / SVG / PNG
↓ 校验与渲染
CI 或本地命令

自动化生成脚本

本地命令读取文档、调用 GPT、产出图源和图片。长期自动化最好，但第一版会引入 API Key、渲染和质量校验成本。

我的建议

优先选 B：把 GPT 当“图源草稿生成器”，但最终把 Mermaid 源文件作为架构资产入库。这样既能利用 GPT，又能让架构图像代码一样可审查、可维护。
