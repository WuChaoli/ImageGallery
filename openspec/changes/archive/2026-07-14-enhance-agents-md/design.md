## Context

当前 `AGENTS.md`（70 行）涵盖项目结构、开发命令、编码风格、docstring 规范、测试指南、PR 指南和架构说明七大块。与 LangChain 的 `CLAUDE.md`（365 行）相比，主要缺口在于：

- 提交/分支/PR 规范只有一句话，缺少 scope 规则、分支命名模板、PR 描述格式
- 测试指南缺少可勾选的 checklist，AI 容易遗漏边界情况
- 没有公共接口稳定性检查机制
- 没有安全红线声明
- 命令只给了 `make xxx` 抽象层，缺少底层等价命令
- 没有机制要求 AI 在修改前检查现有模式

## Goals / Non-Goals

**Goals:**
- 将 AGENTS.md 从 70 行扩展到约 200-250 行，覆盖上述六个缺口
- 每条新增规范都附带具体示例（正反例）
- 新增内容与现有内容风格一致（中文为主，代码示例用英文）
- checklist 格式让 AI 可逐项自检

**Non-Goals:**
- 不改动现有仓库中任何代码文件
- 不修改现有 openspec specs（除非有冲突）
- 不引入外部工具或 CI 流程变更
- 不创建除 AGENTS.md 和 spec 外的其他文档

## Decisions

### 决策 1：结构重组方案

**方案**：保持 AGENTS.md 现有章节结构，在每个章节内补充缺失内容，而非推翻重写。

**理由**：
- 现有章节划分合理（结构→命令→编码→注释→测试→PR→架构）
- 增量修改风险低，易于 review
- LangChain 的最佳实践中，大部分可以自然地归类到现有章节中

### 决策 2：新增章节

**方案**：新增两个章节"公共接口稳定性"和"安全与风险评估"。

**理由**：
- 这两个与现有章节正交，不适合归入已有章节
- LangChain 也是用独立章节承载
- 安全红线需要显眼位置，不能被埋没

### 决策 3：checklist 格式

**方案**：测试指南和接口稳定性检查都用 Markdown 可勾选 checklist（`- [ ]`）格式。

**理由**：
- AI 原生友好，可以在实现时逐项打勾自检
- 比纯文字段落更有约束力
- LangChain 已验证这种格式有效

### 决策 4：命令的底层等价形式

**方案**：在每个 `make xxx` 旁增加 `uv run` 等价命令，标明需要哪些 `--group`。

**理由**：
- 开发环境可能没有 make（尤其 Windows）
- 底层命令便于调试和单独运行
- 与现有 `make lint` 注释中的手动命令风格一致

## Risks / Trade-offs

- **[信息过载]** AGENTS.md 太长可能导致 AI 忽略关键部分 → **Mitigation**: 保持章节结构清晰，每节篇幅克制，关键规范用 `**CRITICAL**` / `**IMPORTANT**` 标注
- **[规范过时]** 规范写得太细，代码演进后不一致 → **Mitigation**: 集中在不会频繁变动的开发流程和代码质量规范上，技术细节留给 openspec specs
- **[AI 不遵守 checklist]** AI 可能跳过检查直接回答"已检查" → **Mitigation**: checklist 项设计为可客观验证的（"检查 __init__.py 导出"），而非主观判断
