# 清洗平台与算子库 v2 文件/类/函数设计

本文档基于 `清洗平台与算子库-v2.md` 继续细化实现设计，只描述第一版清洗平台需要创建的文件、类、函数和调用关系。当前目标是形成可直接进入开发计划的模块边界，不在本文档中编写完整实现代码。

## 设计目标

1. 以 `BasicCleaner([{operator_name: config}, ...])` 作为第一版用户入口。
2. 维护一张图片级 `parameter_table` 宽表和一张图片级 `evaluation_table` 宽表。
3. 使用 `OperatorRegistry` 把逻辑算子映射到唯一 `BackendAdapter`，并在 `BasicCleaner` 内按 backend 分组运行。
4. 后端负责计算参数和后端原生结果，逻辑算子负责生成平台统一评估列。
5. 支持 `run`、`preview`、`state`、`config`、`rerun`、`result`、`export`。
6. 复用现有 `Dataset` 类，不重新设计 Dataset 文件读写抽象。
7. 数据平面使用 Parquet，运行状态使用 JSON manifest；SQLite 可以后续替换 JSON manifest。

### `cleaning/cleaner.py`

职责：

1. 定义 Cleaner 抽象基类。
2. 固定用户侧 API。
3. 约束子类必须提供默认 registry 和 cleaner_type。

类：

```python
class Cleaner(ABC):
    """清洗策略基类。"""

    @abstractmethod
    def run(
        self,
        dataset: Dataset,
        output_dir: str | Path | None = None,
        overwrite: bool = False,
    ) -> "Cleaner":
        """执行当前 Cleaner 配置的全部算子。"""

    @abstractmethod
    def preview(self, limit: int = 20) -> PreviewResult:
        """预览当前 evaluation_table 的清洗结果。"""

    @abstractmethod
    def state(self) -> pd.DataFrame:
        """返回每个算子的运行状态矩阵。"""

    @abstractmethod
    def config(self, operator_configs: OperatorConfigInput) -> "Cleaner":
        """更新一个或多个算子的配置，不主动重算。"""

    @abstractmethod
    def rerun(self, operator_configs: OperatorConfigInput) -> "Cleaner":
        """按传入配置重新计算一个或多个算子。"""

    @abstractmethod
    def result(self, operator_name: str) -> pd.DataFrame:
        """返回指定算子的评估结果列。"""

    @abstractmethod
    def export(self, kind: str, path: str) -> Dataset:
        """导出指定结果视图。"""
```

### `cleaning/basic.py`

职责：

1. 实现 `BasicCleaner`。
2. 按 backend 分组执行启用算子的参数计算。
3. 调用 registry、backend、table、preview、state、export。

类：

```python
@dataclass(frozen=True)
class ResolvedOperatorRun:
    """一次运行中已绑定 spec、backend 和配置的逻辑算子。"""

    parsed_config: ParsedOperatorConfig
    spec: OperatorSpec
    backend: BackendAdapter
    merged_config: dict[str, object]
```

`ResolvedOperatorRun` 是运行期对象，用于保存用户输入配置和 `OperatorSpec.default_config` 合并后的实际配置。`OperatorSpec` 本身不保存用户输入配置。

```python

class BasicCleaner(Cleaner):
    """基础图片清洗策略。"""

    def __init__(
        self,
        operator_configs: OperatorConfigInput,
        output_dir: str | Path | None = None,
        registry: OperatorRegistry | None = None,
    ) -> None:
        """创建基础 Cleaner。"""
```

实例属性：

```text
_operator_configs
_registry
_output_dir
_context
_tables
_state
```

方法：

```python
def run(
    self,
    dataset: Dataset,
    output_dir: str | Path | None = None,
    overwrite: bool = False,
) -> "BasicCleaner":
    """执行全部启用算子，并写出清洗产物。"""
```

执行流程：

```text
parse config
create run context
initialize parameter_table
initialize evaluation_table
resolve all OperatorSpec and BackendAdapter
merge default configs
group operator requests by backend_name
for backend_group in backend_groups:
  call BackendAdapter.compute_parameters(requests)
  update parameter_table
for resolved_operator in resolved_operators:
  call OperatorSpec.evaluate()
  update evaluation_table
  update operator_outputs
apply_final_action()
write_tables()
save state
```

```python
def config(self, operator_configs: OperatorConfigInput) -> "BasicCleaner":
    """更新算子配置，并把相关算子状态标记为 stale。"""
```

```python
def rerun(self, operator_configs: OperatorConfigInput) -> "BasicCleaner":
    """按传入配置重新执行指定算子。"""
```

`rerun` 前置条件：

1. 必须已经执行过 `run`。
2. 必须存在 `_context` 和 `_tables`。
3. 传入算子必须已经存在于 registry。

后端分组运行模型：

```text
用户传入 operator_configs
  -> 逐个解析为 ResolvedOperatorRun
  -> 按 backend.name 分组
  -> 每个 BackendAdapter 接收 list[BackendOperatorRequest]
  -> 后端一次性补齐该组需要的 parameter columns
  -> 每个 OperatorSpec 各自 evaluate
```

这个分组逻辑属于 `BasicCleaner` 的轻量执行能力，不升级为独立 Planner。它只解决同一后端重复读取、重复解码、重复 fastdup 运行的问题，不负责跨后端依赖规划。

执行分层：

```text
BackendAdapter.compute_parameters()
  -> 写 parameter_table / relation table / artifact
  -> 可写入后端原生标签、分组、分数
  -> 不写 evaluation_table

OperatorSpec.evaluate()
  -> 读取 parameter_table
  -> 根据合并后的算子配置生成 evaluation columns
  -> 写 action / reason / score / label 等平台评估列
```

## operators 模块

### `operators/spec.py`

职责：

1. 描述逻辑算子的稳定契约。
2. 绑定唯一后端名称。
3. 提供评估函数入口。
4. 提供默认配置，但不保存用户输入配置。

类：

```python
@dataclass(frozen=True)
class OperatorSpec:
    """逻辑算子规格。"""

    name: str
    category: str
    backend_name: str
    parameter_columns: list[str]
    evaluation_columns: list[str]
    default_config: dict[str, object]
    action_column: str
    reason_column: str
    evaluator: Callable[[pd.DataFrame, dict[str, object]], pd.DataFrame]

    def evaluate(self, parameter_table: pd.DataFrame, config: dict[str, object]) -> pd.DataFrame:
        """基于参数表和配置生成该算子的 evaluation 列。"""
```

`OperatorSpec` 是逻辑算子的静态定义，不是运行期配置对象。用户输入配置保存在 `ParsedOperatorConfig`、`ResolvedOperatorRun`、`CleanerRunContext` 和 `CleanerRunState` 中。执行前由 `merge_default_config()` 合并 `OperatorSpec.default_config` 和用户配置，合并后的配置同时传给 backend 和 evaluator。

评估函数约定：

1. 输入完整 `parameter_table`。
2. 输出必须包含 `image_id` 和 `evaluation_columns`。
3. 不修改输入 DataFrame。
4. 不访问后端工具。
5. 负责生成平台统一的 action、reason、score、label 等评估列。
6. 可以读取后端写入 `parameter_table` 的原生标签、分组和分数，但不直接读取 backend artifact。

```python
@dataclass(frozen=True)
class BackendOperatorRequest:
    """传给后端的单个逻辑算子参数计算请求。"""

    operator_name: str
    parameter_columns: list[str]
    # config 是 OperatorSpec.default_config 和用户输入配置合并后的运行配置。
    config: dict[str, object]
    config_hash: str


@dataclass(frozen=True)
class BackendResult:
    """后端计算结果。"""

    parameter_updates: pd.DataFrame
    relation_updates: dict[str, pd.DataFrame]
    artifact_refs: dict[str, str]
```

```python
class BackendAdapter(ABC):
    """物理后端 adapter 基类。"""

    name: str

    @abstractmethod
    def compute_parameters(
        self,
        dataset: Dataset,
        parameter_table: pd.DataFrame,
        requests: list[BackendOperatorRequest],
        artifacts_dir: str | Path,
    ) -> BackendResult:
        """按一组逻辑算子请求批量计算缺失或需要重算的参数字段。"""
```

后端约定：

1. 不直接写 `evaluation_table`。
2. 不生成平台 action、reason 或 `final_action`。
3. 可以写 artifact 文件，但必须通过 `artifact_refs` 返回引用。
4. `parameter_updates` 必须包含 `image_id`。
5. 后端一次接收同一 backend 下的多个逻辑算子请求，并自行合并需要计算的参数列。
6. 如果某列已存在且配置未变化，后端可以返回空更新。
7. 后端可以根据 `requests[*].operator_name` 做少量分支，但不应生成平台评估列。
8. 后端可以产出原生标签、分组、分数或 issue 类型，这些字段属于参数表字段，由逻辑算子评估函数决定是否采纳。

## 调用链路

### `run(dataset)`

```text
BasicCleaner.run(dataset)
  -> parse_operator_configs()
  -> create_run_context()
  -> initialize_parameter_table()
  -> initialize_evaluation_table()
  -> create_default_registry()
  -> for each operator:
       registry.resolve(operator_name)
       merge_default_config()
       build ResolvedOperatorRun
  -> group ResolvedOperatorRun by backend_name
  -> for each backend group:
       backend.compute_parameters(requests)
       update_parameter_columns()
       update backend artifact refs
  -> for each resolved operator:
       spec.evaluate()
       update_evaluation_columns()
       update_operator_outputs()
       update OperatorRunState
  -> apply_final_action()
  -> write_tables()
  -> JsonRunStateStore.save()
```

### `config(operator_configs)`

```text
BasicCleaner.config(operator_configs)
  -> parse_operator_configs()
  -> replace config for matching operator
  -> mark operator state as stale
  -> save state if run exists
```

### `rerun(operator_configs)`

```text
BasicCleaner.rerun(operator_configs)
  -> _require_run()
  -> parse_operator_configs()
  -> for each passed operator:
       registry.resolve(operator_name)
       merge_default_config()
       build ResolvedOperatorRun
  -> group ResolvedOperatorRun by backend_name
  -> for each backend group:
       backend.compute_parameters(requests)
       update_parameter_columns()
       update backend artifact refs
  -> for each resolved operator:
       spec.evaluate()
       update_evaluation_columns()
       update operator state
  -> apply_final_action()
  -> write_tables()
  -> JsonRunStateStore.save()
```

### `preview()`

```text
BasicCleaner.preview()
  -> _require_run()
  -> build_preview(evaluation_table, operator_outputs)
```

### `export(kind, path)`

```text
BasicCleaner.export(kind, path)
  -> _require_run()
  -> export_cleaning_result(kind, tables, path)
  -> Dataset.write()
```

## 第一版实现顺序

1. 实现 `config.py`、`errors.py` 和对应单测。
2. 实现 `spec.py`、`registry.py`、`backends/base.py` 和 registry 单测。
3. 实现 `tables.py`、`preview.py`、`export.py` 和宽表单测。
4. 实现 `state.py` 和 JSON state 单测。
5. 实现 `builtin.py` 中不依赖重型第三方库的 evaluator。
6. 实现 `pillow_backend.py`、`hash_backend.py`。
7. 实现 `BasicCleaner.run/preview/state/result/export/config/rerun` 的最小闭环，其中 `run` 和 `rerun` 必须按 backend 分组调用 `compute_parameters`。
8. 实现 `opencv_backend.py`。
9. 最后实现或占位 `fastdup_backend.py`，明确依赖缺失错误。

## 非目标

1. 不引入 DAG、Planner、ExecutionPack。
2. 不在第一版实现 SQLite state store。
3. 不为每个算子创建独立结果表。
4. 不让 backend 写 `final_action`。
5. 不让 evaluator 直接读取图片或调用第三方工具。
6. 不在清洗模块重新实现 Dataset 文件读写。
