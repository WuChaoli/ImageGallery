# 数据集管理与可视化架构

本文档从总架构文档中拆分而来，承接对应功能域的详细架构设计。总架构文档只保留总体把控、模块边界和跨模块约束。

## 模块定位

数据集管理与可视化模块负责 Dataset 文件的读写、扫描、导出和 Notebook/静态 HTML 查看能力。

## 职责范围

1. 提供 Dataset.from_path、preview、scan、count、export 和 fingerprint 等能力。
2. 管理 raw、clean、dropped、full 等数据集文件的读取与导出。
3. 提供表格预览、图片网格、重复组查看、dropped 候选查看和静态 HTML 报告。
4. 通过抽样和 limit 控制可视化规模，避免全量浏览。

## 核心对象

1. Dataset
2. DatasetReader
3. DatasetWriter
4. DatasetExporter
5. DatasetViewer
6. thumbnail cache
7. HTML report

## 核心流程

Dataset Path -> Dataset 读取/扫描 -> 预览或查询 -> 可视化展示/报告导出 -> 训练、标注或分析消费。

## 数据 / 状态 / 配置契约

1. Dataset 只表达数据集文件能力，不理解 raw、clean、dropped、full 的业务生命周期。
2. 导出配置归属本模块，包括 output_format、address_policy、selected_columns、compression、output_path 和报告抽样限制。
3. Notebook 和 HTML 报告默认使用抽样缩略图，不直接暴露敏感 source_uri。

## 与其他模块边界

1. 依赖存储系统读取图片和缩略图，依赖 schemas 保持字段契约。
2. 读取清洗平台的节点结果和状态矩阵，但不修改清洗结果。
3. 报告能力可以写入文件和摘要，但不承担任务调度职责。

## V1 范围与非目标

1. V1 支持 Parquet 为主的数据集读写和 Notebook/静态 HTML 查看。
2. V1 不实现 Web 前端、在线编辑、实时刷新和全量图片浏览。

## 详细设计

### 8. 数据集管理设计

#### 8.1 模块定位

数据集管理是公共基础能力之一，负责提供数据集文件的读写、预览、过滤和导出能力。

数据集管理不负责处理图片，不负责执行清洗算子，也不负责判断数据集属于 raw、clean、dropped 或 full。raw、clean、dropped、full 只是上层业务对不同输出文件的命名约定，不是数据集管理层的强制阶段模型。

第一版数据集管理应保持轻量：

```text
数据集是文件
阶段是命名
路径由调用方决定
Dataset 类提供读写与导出能力
```

#### 8.2 数据集最小定义

第一版中，一份数据集可以被定义为一个 Dataset 对象。Dataset 对象用于包裹一个或多个可读取的数据文件，并提供统一的读取、预览、过滤和导出能力。

最小描述包括：

```text
Dataset
dataset_path
format
schema
```

其中 dataset_path 指向当前环境可访问的数据集文件路径。第一版本地模式推荐使用本地绝对路径。

示例：

```text
/data/project_a/dropped.parquet
file:///data/project_a/clean.parquet
```

数据集管理层不要求 dataset_path 遵守固定目录结构。

Dataset 是数据集文件的轻量对象封装，不表达 raw、clean、dropped、full 等阶段语义。

#### 8.3 数据集语义边界

数据集管理层不理解阶段语义。

例如以下文件名可以表达业务含义：

```text
raw.parquet
clean.parquet
dropped.parquet
full.parquet
quality_node_result.parquet
duplicate_node_status_matrix.parquet
```

但这些名称只是调用方或任务方约定。数据集管理层只把它们视为可读写的数据集文件。

阶段语义由上层模块决定：

1. 图片导入模块可以输出名为 raw.parquet 的数据集。
2. 清洗平台的归并函数可以输出 clean.parquet、dropped.parquet、full.parquet。
3. 逻辑算子可以输出 node_result.parquet 和 node_status_matrix.parquet。
4. 用户可以自定义输出文件名和输出路径。

#### 8.4 数据集读写能力

第一版数据集管理应优先提供 Dataset 类能力，而不是让上层模块到处直接传递路径字符串。

```text
Dataset.from_path(dataset_path)
Dataset.write(data, output_path)
Dataset.scan(columns=None, filters=None)
Dataset.preview(limit=100)
Dataset.count()
Dataset.validate_readable()
```

这些能力可以用于导入、清洗、可视化和导出等不同模块。路径用于定位数据集文件，Dataset 用于操作数据集。

导入任务、CleaningRecipe、ExecutionPack 和逻辑算子结果标准化过程应尽量接收 Dataset 对象作为输入；当需要写出新数据集时，由调用方提供 output_path，写出完成后返回新的 Dataset 对象。

数据集管理层只负责数据文件本身的读写，不负责维护任务状态、算子结果语义或归并策略。

#### 8.5 数据集导出能力

导出能力需要区分内部保留字段和外部共享字段。

平台内部数据集默认使用 image_uri 作为图片访问地址。面向外部训练框架、通用 Parquet 工具或临时分析脚本时，仍然保留 image_uri，除非导出配置要求复制图片并改写为新的导出地址。

导出能力建议支持：

```text
Dataset.export(
  output_dataset_path,
  output_format,
  address_policy
)
```

其中 address_policy 用于控制图片地址处理方式：

1. keep：保留原始 image_uri。
2. copy：复制图片到导出目录，并把 image_uri 改写为导出目录下的新绝对地址。

#### 8.6 不做内容

第一版数据集管理不做以下内容：

1. 不做数据集版本管理。
2. 不做数据集分支与合并。
3. 不强制数据集目录结构。
4. 不强制 manifest 文件。
5. 不把 raw、clean、dropped、full 固化为数据集阶段模型。
6. 不把图片级数据集明细写入数据库。

如后续平台需要版本管理、分支合并或数据集治理能力，可以在更上层单独设计，不影响当前数据集读写能力。

#### 8.7 设计原则

1. 数据集是文件，不是阶段。
2. 文件名可以表达业务语义，但数据集管理层不解析阶段含义。
3. 输出路径由调用方决定，数据集管理层不强制目录规范。
4. 第一版不要求 manifest。
5. Dataset 类是数据集文件的主要操作入口。
6. 路径用于定位，Dataset 用于操作。
7. 图片级元数据和处理结果优先保存在 Parquet 文件中。

### 14. 数据集可视化设计

#### 14.1 模块定位

第一版数据集可视化不实现 Web 页面，也不引入后端服务。可视化能力作为 Python 包中的辅助能力提供，主要服务于 Jupyter Notebook 调试、清洗结果检查和离线报告导出。

数据集可视化模块只读取 Dataset、CleaningRecipe、ExecutionPlan、逻辑算子结果、逻辑算子状态矩阵和物理执行报告，不执行清洗算法，不修改数据集，不改变清洗归并结果。

#### 14.2 第一版可视化形态

第一版支持两类最小可视化形态：

1. Notebook 内查看：返回 DataFrame、统计摘要和图片网格，方便数据工程师在 Jupyter 中交互式检查。
2. 静态 HTML 报告：导出离线 HTML 文件，用于分享清洗结果样本、重复组和异常样本。

不实现内容：

1. 不实现 Web 服务。
2. 不实现前端页面。
3. 不实现在线标注。
4. 不实现可视化中的数据编辑。
5. 不要求实时刷新。

#### 14.3 DatasetViewer

第一版可以提供 DatasetViewer 作为可视化入口。

DatasetViewer 是 Python 包中的辅助类，负责把 Dataset、逻辑算子结果、逻辑算子状态矩阵和物理执行摘要转换为 Notebook 友好的展示对象。

典型能力包括：

```text
DatasetViewer.show_grid(dataset)
DatasetViewer.show_operator_result(cleaning_run, operator_id)
DatasetViewer.show_duplicate_groups(cleaning_run, operator_id)
DatasetViewer.show_execution_plan(cleaning_run)
DatasetViewer.show_dropped_candidates(cleaning_run, merge_policy)
DatasetViewer.export_html(cleaning_run, output_path)
```

这些函数只做读取和展示，不写入清洗结果，不更新归并策略。

#### 14.4 表格查看

表格查看用于快速检查数据集和节点结果。

典型入口包括：

```text
Dataset.preview(limit)
Dataset.summary()
cleaning.get_status()
cleaning.get_operator_result(operator_id)
cleaning.get_operator_status_matrix(operator_id)
cleaning.get_execution_plan()
cleaning.preview_merge(policy)
```

表格查看主要支持以下场景：

1. 查看数据集总量、字段、基础统计。
2. 查看每个逻辑算子和物理执行包的运行状态。
3. 查看某个算子的命中图片。
4. 查看 dropped 候选图片及原因。
5. 查看重复组列表。
6. 查看异常尺寸、异常格式、低质量图片列表。

#### 14.5 图片网格预览

图片网格预览用于在 Notebook 中直接查看样本图片。

实现方式：

1. 从 Dataset 或节点结果中读取 image_id、image_uri 和展示字段。
2. 直接通过 image_uri 读取当前环境可访问的图片。
3. 按 limit、筛选条件或分组条件读取图片。
4. 在 Notebook 中展示缩略图网格。

每张图片下方可以展示少量关键信息：

1. image_id。
2. 图片尺寸。
3. 文件大小。
4. 算子命中状态。
5. 丢弃原因。
6. score、threshold 等算子输出字段。
7. duplicate_group_id 等分组字段。

#### 14.6 重复组预览

重复检测是清洗查看中的重要场景。重复组预览可以把同一 duplicate_group_id 的图片展示在同一行或同一区块中，方便人工判断。

示例能力：

```text
DatasetViewer.show_duplicate_groups(
  graph,
  node_id="duplicate_check",
  max_groups=20,
  group_size=8
)
```

重复组预览只负责展示节点结果，不直接决定保留哪一张图片。保留策略应由用户后续在归并策略中表达。

#### 14.7 静态 HTML 报告

静态 HTML 报告用于把清洗结果导出为离线可查看文件。

报告可以包含：

1. 数据集总览。
2. 各算子命中数量。
3. 各算子失败数量。
4. dropped 候选样本。
5. 重复组样本。
6. 异常尺寸样本。
7. 低质量样本。
8. 节点报告摘要。

HTML 报告不依赖后端服务。为保证报告稳定性，第一版推荐在导出报告时生成缩略图目录，并让 HTML 引用本地缩略图，而不是直接依赖 MinIO presigned URL。

示例目录：

```text
reports/
  cleaning_preview.html
  thumbnails/
    image_000001.jpg
    image_000002.jpg
```

#### 14.8 设计原则

1. 可视化模块只读，不修改数据集和清洗结果。
2. 第一版优先服务 Jupyter Notebook 调试。
3. 图片展示通过 image_uri 访问图片。
4. 大规模数据集默认只展示抽样结果，不一次性加载全部图片。
5. 重复组、异常样本和 dropped 候选是第一版重点查看场景。
6. 静态 HTML 报告用于离线分享，不引入服务端和前端工程。
7. 可视化依赖 Dataset、节点结果和节点状态矩阵，不依赖数据库中的图片级明细。
8. 可视化可以使用 SQLite 记录缩略图缓存索引和报告产物索引，但不存储缩略图二进制和图片级处理明细。
