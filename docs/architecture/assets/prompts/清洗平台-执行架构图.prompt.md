# 清洗平台执行架构图生成提示词

## 用途

用于通过 `gpt-image-2` 生成《清洗平台与算子库架构》模块文档中的清洗平台执行架构图。

## 生成提示词

```text
Use case: infographic-diagram
Asset type: 中文技术架构文档中的清洗平台详细架构图

请生成一张 16:9 横版中文技术白板风架构图，标题为「清洗平台执行架构」。

用途：用于《清洗平台与算子库架构》模块文档，解释清洗平台从原始数据集到清洗结果产物的完整执行链路。

整体风格：白色背景，技术白板风，专业、克制、清晰。使用浅灰、浅蓝、浅绿色。模块盒子清楚，箭头方向明确，分区留白充足。不要深色背景，不要霓虹，不要 3D，不要人物，不要服务器机房，不要代码屏幕，不要复杂装饰。

核心表达：
这不是通用任务平台图，而是清洗领域自己的执行架构图。重点突出：逻辑算子是用户侧稳定接口，执行包是内部优化接口；用户侧逻辑算子隔离，执行侧物理执行融合，结果侧按逻辑算子还原。

画面布局：
1. 主链路从左到右，使用粗箭头：
「原始数据集」→「清洗配方」→「逻辑算子列表」→「算子注册表」→「执行规划」→「执行计划」→「执行包」→「产物注册」→「结果标准化」→「逻辑算子结果」→「归并策略」→「结果数据集」。

2. 「执行包」区域要画成内部优化层，可以包含多个并列小盒子：
「图片元数据包」
「图片解码包」
「图片质量包」
「视觉相似包」
「图片审计包」
请用箭头或合并符号表达：多个逻辑算子可以被规划到同一个执行包，共享读取、解码、特征和索引。

3. 「结果标准化」之后要分成三个标准产物：
「算子结果」
「状态矩阵」
「算子报告」
这三个产物必须显示为每个逻辑算子独立可查看的结果。

4. 「归并策略」之后要输出三个数据集：
「完整数据集」
「保留数据集」
「丢弃数据集」
旁边可以放两个小标签：「预览归并」「正式归并」。

5. 底部画一条公共基础能力层，使用浅灰底座，不作为主流程节点：
「图片存储」
「数据集文件」
「运行状态」
「产物清单」
「报告文件」
「错误恢复」
用细虚线连接到主链路中的导入、执行包、产物注册、结果标准化、归并策略等区域，表示它们依赖这些基础能力。

6. 顶部可以放三条原则短句，作为小标签：
「用户侧：逻辑算子隔离」
「执行侧：物理执行融合」
「结果侧：按逻辑算子还原」

文字要求：
全部使用中文短标签。文字要清晰、端正、不要变形、不要错别字。不要使用长段文字。不要把英文类名作为主要标签。

不要出现以下已废弃设计或词语：
任务平台、底层任务框架、Graph、Node、GraphRuntime、TaskPlanner、ExecutionTask、任务链、通用 DAG、通用节点、统一任务运行时。

最终效果：读者一眼能看懂清洗平台如何把用户配置的细粒度逻辑算子，经由算子注册表和执行规划，融合为执行包执行，再标准化为逻辑算子结果，最后通过归并策略产出完整、保留、丢弃数据集。
```
