# 清洗平台算子与执行包映射图生成提示词

## 用途

用于通过 `gpt-image-2` 生成《清洗平台与算子库架构》模块文档中的算子与执行包映射图。

## 生成提示词

```text
Use case: infographic-diagram
Asset type: 中文技术架构文档中的算子与执行包映射架构图

请生成一张 16:9 横版中文技术白板风架构图，标题为「算子与执行包映射」。

用途：用于《清洗平台与算子库架构》模块文档，解释用户侧逻辑算子如何通过算子注册表和执行规划，映射并融合到内部执行包，同时复用共享产物。

整体风格：白色背景，技术白板风，专业、克制、清晰。使用浅灰、浅蓝、浅绿色。模块盒子清楚，箭头方向明确，分区留白充足。不要深色背景，不要霓虹，不要 3D，不要人物，不要服务器机房，不要代码屏幕，不要复杂装饰。

画面布局：

1. 左侧为「逻辑算子分类」区域，表达用户侧稳定能力。请使用中文短标签，分成九类：
「格式算子」
「尺寸算子」
「质量算子」
「特征算子」
「重复算子」
「分布算子」
「标签算子」
「内容算子」
「转换算子」
左侧可以用浅蓝模块盒子，标题旁标注「用户侧：按能力配置」。

2. 中部为「算子注册表」和「执行规划」两个核心模块：
「算子注册表」负责能力描述、输入需求、输出契约、候选后端。
「执行规划」负责依赖分析、缓存识别、执行包融合、复用计划。
请用箭头表达：逻辑算子分类 → 算子注册表 → 执行规划。

3. 右侧为「执行包类型」区域，表达内部物理执行单元。请用浅绿色模块盒子，分成七类：
「图片元数据包」
「图片解码包」
「图片质量包」
「视觉相似包」
「图片审计包」
「自研特征包」
「转换处理包」
右侧标题旁标注「执行侧：融合共享计算」。

4. 从左侧逻辑算子到右侧执行包之间，必须体现多对一映射：
多个质量算子可以进入同一个「图片质量包」；
多个重复、离群、聚类类算子可以进入同一个「视觉相似包」；
格式和尺寸相关能力可以共享「图片元数据包」和「图片解码包」；
转换类能力进入「转换处理包」。
请使用合流箭头、束状箭头或映射线表达多对一融合关系。

5. 底部为「共享产物层」，用浅灰底座表达，不作为用户可配置算子：
「基础元数据」
「图片哈希」
「解码指标」
「质量指标」
「视觉特征」
「相似关系」
「索引」
「审计摘要」
「缩略图」
请用细线从执行包指向共享产物层，表达执行包会写出可复用产物。

6. 底部或右下角加一个小的「结果还原」区域：
「标准化结果」
「状态矩阵」
「算子报告」
表达：执行包输出不会直接替代逻辑算子结果，必须经过结果标准化，回到每个逻辑算子的独立结果。

7. 画面顶部放两条原则短句：
「逻辑算子按能力命名，不按工具命名」
「执行包可替换，算子语义保持稳定」

文字要求：
全部使用中文短标签。文字清晰、端正、不要变形、不要错别字。不要使用长段文字。不要把英文类名作为主要标签。

不要出现以下已废弃设计或词语：
任务平台、底层任务框架、Graph、Node、GraphRuntime、TaskPlanner、ExecutionTask、任务链、通用 DAG、通用节点、统一任务运行时。

不要把执行包画成用户直接配置的算子；不要让执行包直接生成保留数据集、丢弃数据集或完整数据集。

最终效果：读者一眼能看懂清洗算子库的关键设计：用户配置的是稳定的细粒度逻辑算子；系统通过注册表和执行规划把它们映射到可共享计算的执行包；执行包写出共享产物；结果再被标准化回每个逻辑算子的独立结果。
```
