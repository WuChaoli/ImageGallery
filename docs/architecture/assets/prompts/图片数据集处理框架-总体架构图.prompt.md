# 图片数据集处理框架总体架构图生成提示词

## 用途

用于通过 `gpt-image-2` 生成《图片数据集处理框架》总体架构文档中的总览架构图。

## 生成提示词

```text
请生成一张 16:9 横版中文技术架构图，用于《图片数据集处理框架》总体架构文档。

图的目标不是简单流程图，而是一张有层次、有边界、有数据产物的系统总览架构图。整体风格是技术白板风：白色背景、清晰分区、模块盒子、数据流箭头、少量说明性标注。视觉专业、克制、适合架构评审，不要做成炫酷科技海报。

画面结构：

1. 从左到右是主数据流：
   「外部数据来源」
   →「图片导入」
   →「原始数据集」
   →「清洗平台」
   →「完整数据集 / 保留数据集 / 丢弃数据集」
   →「查看 / 报告 / 导出」

2. 图片导入区域包含以下短标签：
   「来源读取」
   「存储写入」
   「基础元数据抽取」
   「原始数据集构建」
   「导入报告」

3. 清洗平台区域要画得更细，并突出核心设计：
   「清洗配方」
   「逻辑算子」
   「执行规划」
   「执行包」
   「结果标准化」
   「归并策略」

   请重点表达：
   用户配置的是细粒度「逻辑算子」；
   系统内部由「执行规划」把可共享计算融合成「执行包」；
   「结果标准化」把物理执行结果还原成每个逻辑算子的结果；
   「归并策略」再生成「完整数据集」「保留数据集」「丢弃数据集」。

   请用清晰的局部结构表达：
   「逻辑算子隔离，物理执行融合」。

4. 输出区域包含：
   「完整数据集」
   「保留数据集」
   「丢弃数据集」
   「数据集查看」
   「静态报告」
   「数据导出」

5. 画面底部画一条公共基础能力层，不要把它画成主流程节点：
   「图片存储」
   「数据集文件」
   「运行状态」
   「产物清单」
   「报告文件」
   「错误恢复」

   这条基础能力层用横向底座或底部泳道表达，表示导入、清洗、查看等模块都会依赖它。

6. 画面顶部可以画一条轻量控制面：
   「配置」
   「进度」
   「恢复策略」
   「报告摘要」

   控制面通过细线连接导入、清洗、查看几个区域，表示它们提供状态管理和恢复能力，但不要画成任务平台。

7. 数据产物关系要清楚：
   图片文件进入「图片存储」；
   数据集事实写入「数据集文件」；
   运行状态写入「运行状态」；
   中间产物写入「产物清单」；
   报告写入「报告文件」；
   「原始数据集」「完整数据集」「保留数据集」「丢弃数据集」是核心数据集产物。

8. 视觉要求：
   白底，横向架构图，分区清晰，箭头方向明确，模块之间留白充足。
   使用浅灰、浅蓝、浅绿作为主色。
   清洗平台区域可以用稍微突出的浅蓝色。
   公共基础能力层可以用浅灰底座。
   不要使用深色背景、霓虹、3D、人物、服务器机房、代码屏幕、抽象科技装饰。

9. 文字要求：
   图中只放短中文标签，不要生成长段文字。
   所有模块名尽量使用中文。
   文字要清晰、端正、不要变形、不要出现错别字。

10. 不要出现以下已废弃设计：
   任务平台、底层任务框架、通用图编排、通用节点、通用有向无环图、任务链、统一任务运行时。

最终画面要让读者一眼看懂：
这是一个本地优先的图片数据集处理框架；图片先被导入为原始数据集，再进入清洗平台；清洗平台坚持用户侧逻辑算子细粒度、执行侧物理执行融合；最终产出完整数据集、保留数据集、丢弃数据集，并支持查看、报告、导出和失败恢复。
```
