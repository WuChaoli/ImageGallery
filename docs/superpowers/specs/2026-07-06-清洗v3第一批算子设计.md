# 清洗 v3 第一批算子设计

## 背景

当前清洗 v3 平台已经具备最小闭环：`BasicCleaner` 可以解析逻辑算子配置，收集参数需求，调用 `ParameterComputer` 生成 `parameter_table`，再由逻辑算子 evaluator 生成 `evaluation_table`、`final_action` 和导出视图。

现有默认算子只有 `format.decode_check` 和 `size.dimension_check`。第一批扩展目标是形成通用图片数据集质量基线，而不是针对当前 Notebook 或 MinIO 测试集做特化。

## 目标

第一批算子需要满足以下目标：

1. 覆盖通用图片数据集最常见的基础质量问题。
2. 不引入 embedding、ANN、语义相似或重型模型能力。
3. 保持用户侧算子按能力命名，底层实现细节留在 `ParameterComputer` 内部。
4. 保持 v3 的两层职责：参数计算只生产参数，逻辑算子只评估 action 和 reason。
5. 支持 Notebook 中直观看到 `parameter_table`、`evaluation_table`、`preview()` 和 `export()` 的结果。

## 非目标

第一批不做以下内容：

1. `duplicate.near_duplicate_check`。
2. `distribution.cluster_check` 和 `distribution.outlier_check`。
3. embedding、ANN index、语义相似、CLIP 或其他深度模型能力。
4. NSFW、OCR、水印、caption、文本图等内容理解类算子。
5. 跨 run 缓存、重型 planner、分布式执行或批级恢复。
6. 在检测类算子中删除、移动或修改图片资产。

## 算子范围与优先级

第一批按“先保证数据可用，再提升视觉质量，最后处理跨图片问题”的顺序推进。

### P0：已有基线

```text
format.decode_check
size.dimension_check
```

### P1：表派生尺寸

```text
size.aspect_ratio_check
size.megapixel_check
```

`size.megapixel_check` 复用 `width` 和 `height`，实现成本低，但能发现低信息量缩略图和异常超大图，因此纳入第一批。

### P2：图片质量包

```text
quality.blur_check
quality.brightness_check
quality.contrast_check
content.blank_image_check
```

这些算子共享同一个图片级质量计算单元，避免每个算子重复读取和解码图片。

### P3：全局完全重复

```text
duplicate.exact_duplicate_check
```

完全重复不需要 embedding，可以通过内容哈希和数据集级分组实现。它是第一批中唯一需要 dataset global 阶段的能力，用于验证 v3 全局参数计算路径。

## ParameterComputer 设计

第一批使用 5 个计算单元。

### image_metadata_computer

阶段：`image_batch`

产出：

```text
width
height
format
decode_ok
decode_error
file_size
```

服务：

```text
format.decode_check
size.dimension_check
```

### table_derived_computer

阶段：`table_derived`

输入：

```text
width
height
```

产出：

```text
aspect_ratio
megapixels
```

服务：

```text
size.aspect_ratio_check
size.megapixel_check
```

该计算单元只读取 `parameter_table`，不读取图片。

### image_quality_computer

阶段：`image_batch`

输入：

```text
decoded_image
grayscale_image
```

产出：

```text
blur_score
brightness_score
contrast_score
blank_score
```

服务：

```text
quality.blur_check
quality.brightness_check
quality.contrast_check
content.blank_image_check
```

第一版质量分数采用轻依赖实现，优先使用 Pillow 和 numpy；如果使用 OpenCV，需要在依赖缺失时给出明确错误。初始语义如下：

1. `blur_score`：灰度图拉普拉斯方差或等价清晰度分数，越高表示越清晰。
2. `brightness_score`：灰度亮度均值，范围约为 0 到 255。
3. `contrast_score`：灰度亮度标准差，越高表示对比越强。
4. `blank_score`：空白或纯色置信度，范围 0 到 1，越高越像空白图。

### image_hash_computer

阶段：`image_batch`

输入：

```text
raw_bytes
```

产出：

```text
content_hash
```

服务：

```text
duplicate.exact_duplicate_check
```

第一版使用图片原始字节的稳定哈希生成 `content_hash`，用于完全重复检测。后续如果需要“视觉相同但编码不同”的重复检测，应扩展为 `phash` 或近重复算子，不混入当前完全重复定义。

### duplicate_group_computer

阶段：`dataset_global`

输入：

```text
content_hash
```

产出：

```text
exact_duplicate_group_id
exact_duplicate_count
```

可选 relation 产物：

```text
relations/duplicate_pairs.parquet
```

第一版完全重复按相同 `content_hash` 分组。单图唯一组的 `exact_duplicate_group_id` 可以为空，重复组使用稳定 group id。`exact_duplicate_count` 表示该图片所在重复组数量，唯一图片为 1。

## 逻辑算子契约

### format.decode_check

```text
required_parameters:
  - decode_ok
  - decode_error
evaluation_columns:
  - decode_action
  - decode_reason
default_config:
  action: drop
```

解码失败时触发 action，reason 使用 `decode_error`。

### size.dimension_check

```text
required_parameters:
  - width
  - height
evaluation_columns:
  - dimension_action
  - dimension_reason
default_config:
  min_width: 1
  min_height: 1
  action: drop
```

小于硬尺寸下限时触发 action。

### size.aspect_ratio_check

```text
required_parameters:
  - aspect_ratio
evaluation_columns:
  - aspect_ratio
  - aspect_ratio_action
  - aspect_ratio_reason
default_config:
  min_ratio: 0.2
  max_ratio: 5.0
  action: review
```

低于 `min_ratio` 或高于 `max_ratio` 时触发 action。`aspect_ratio = width / height`。

### size.megapixel_check

```text
required_parameters:
  - megapixels
evaluation_columns:
  - megapixels
  - megapixel_action
  - megapixel_reason
default_config:
  min_megapixels: 0.01
  max_megapixels: null
  action: review
```

低于 `min_megapixels` 或高于 `max_megapixels` 时触发 action。`max_megapixels` 为 `null` 表示不启用上限。

### quality.blur_check

```text
required_parameters:
  - blur_score
evaluation_columns:
  - blur_score
  - blur_action
  - blur_reason
default_config:
  min_score: 100.0
  action: review
```

低于 `min_score` 时触发 action。该默认值是第一版经验阈值，用于形成可测试闭环，后续可通过 Notebook 样本校准。

### quality.brightness_check

```text
required_parameters:
  - brightness_score
evaluation_columns:
  - brightness_score
  - brightness_action
  - brightness_reason
default_config:
  min_score: 30.0
  max_score: 225.0
  action: review
```

低于 `min_score` 视为过暗，高于 `max_score` 视为过曝。

### quality.contrast_check

```text
required_parameters:
  - contrast_score
evaluation_columns:
  - contrast_score
  - contrast_action
  - contrast_reason
default_config:
  min_score: 10.0
  action: review
```

低于 `min_score` 时视为低对比度。该默认值是第一版经验阈值。

### content.blank_image_check

```text
required_parameters:
  - blank_score
evaluation_columns:
  - blank_score
  - blank_action
  - blank_reason
default_config:
  threshold: 0.98
  action: drop
```

`blank_score >= threshold` 时触发 action。空白图默认 drop，因为它通常代表占位图、坏样本或无信息样本。

### duplicate.exact_duplicate_check

```text
required_parameters:
  - exact_duplicate_group_id
  - exact_duplicate_count
evaluation_columns:
  - exact_duplicate_group_id
  - exact_duplicate_count
  - exact_duplicate_action
  - exact_duplicate_reason
default_config:
  keep: first
  action: drop
```

重复组中保留 `parameter_table` 输入顺序中的第一张图片，其余图片触发 action。该规则与 raw Dataset 行顺序一致，避免使用 `image_id` 字符串排序改变用户原始数据顺序。

## 默认 action 策略

默认 `drop`：

```text
format.decode_check
size.dimension_check
content.blank_image_check
duplicate.exact_duplicate_check
```

默认 `review`：

```text
size.aspect_ratio_check
size.megapixel_check
quality.blur_check
quality.brightness_check
quality.contrast_check
```

原则是：确定坏图和确定重复图可以默认 drop；主观质量问题默认 review，避免第一版误删有价值图片。

## 数据流

第一批沿用 v3 三阶段执行：

```text
Dataset
  -> initialize parameter_table / evaluation_table
  -> image_batch: metadata + quality + hash
  -> table_derived: aspect_ratio + megapixels
  -> dataset_global: exact duplicate groups
  -> evaluate logical operators
  -> apply_final_action
  -> preview() / result() / export()
```

`evaluation_table` 只保存逻辑算子的判断结果、action、reason、score 和最终归并列。`parameter_table` 不保存 action、reason 或 final decision。

## 平台补强

第一批实现时需要同步补齐两个平台能力。

### relation_updates 落盘

`ParameterResult` 已经包含 `relation_updates`。`BasicCleaner` 需要能够把 relation table 写入 `relations/` 并在运行状态中记录路径。

第一批 `duplicate.exact_duplicate_check` 可以只依赖 `exact_duplicate_group_id` 和 `exact_duplicate_count` 完成评估；如果 `duplicate_group_computer` 产出 `duplicate_pairs.parquet`，平台应能写入并记录它。

### run state 字段补齐

`state.json` 需要补齐以下字段：

```text
parameter_config_hashes
parameter_manifest_path
relation_paths
started_at
finished_at
```

第一批所有参数计算配置可以先使用 `default` 哈希，但字段必须存在，便于后续区分“评估配置变化”和“参数计算配置变化”。

## 错误处理

### 单图解码失败

解码失败不应中断整批运行：

1. `image_metadata_computer` 写入 `decode_ok=False` 和 `decode_error`。
2. `image_quality_computer` 和 `image_hash_computer` 对该图写入空参数。
3. evaluator 基于空参数和 `decode_ok` 给出可解释结果。

### 依赖缺失

如果质量计算依赖 OpenCV 而环境缺失，错误信息必须包含：

```text
computer name
affected operator names
suggested dependency or fallback
```

第一版优先使用 Pillow 和 numpy 完成基础质量分数，减少依赖风险。

### 参数缺失

保留现有失败策略：

1. registry 缺少参数生产者时，`run()` 在参数计算前失败。
2. evaluator 缺少 required parameters 时，`OperatorSpec.evaluate()` 失败。
3. evaluator 输出缺少声明列时，`OperatorSpec.evaluate()` 失败。

## 测试验收

### 单元测试

需要覆盖：

1. 每个 `ParameterComputer` 的输出列、跳过坏图、`parameter_manifest`。
2. 每个 evaluator 的 action/reason 边界。
3. 默认 registry 包含第一批全部算子。
4. `duplicate_group_computer` 的 `keep=first` 逻辑。
5. relation table 写入路径和 state 路径记录。

### 集成测试

构造小型 synthetic dataset，至少包含：

```text
normal image
broken image
small image
extreme aspect ratio image
low megapixel image
blurred image
dark image
blank image
exact duplicate image
```

验证：

1. `parameter_table` 包含第一批参数列。
2. `evaluation_table` 包含第一批评估列和最终归并列。
3. `preview()` 统计 clean、review、dropped 数量正确。
4. `result(operator_name)` 返回对应算子输出列。
5. `export("clean" | "review" | "dropped" | "full")` 保留预期行。
6. 多个质量算子共享同一次图片读取和解码上下文。

### Notebook 验收

更新 `notebooks/cleaning_v3_builtin_test.ipynb`，展示第一批算子完整闭环：

1. 创建或读取验证数据集。
2. 运行第一批默认算子。
3. 展示 `state()`、`preview()`、`operator_summary`。
4. 查看 `parameter_table` 和 `evaluation_table` 的关键列。
5. 导出 `clean`、`review`、`dropped`、`full`。

Notebook 不负责证明所有边界条件，边界行为由单元测试和集成测试覆盖。

## 成功标准

第一批完成后，应满足：

1. 默认 registry 注册本设计中的全部第一批算子。
2. `BasicCleaner` 可以一次运行第一批算子并生成完整产物。
3. 参数计算与逻辑评估职责清晰，没有逻辑算子直接读取图片。
4. 解码失败、质量异常、空白图和完全重复图都有可解释 action/reason。
5. 所有新增单元测试、集成测试和 Notebook 验证通过。
6. 仍然不包含 embedding、near duplicate、cluster、outlier 或重型模型能力。
