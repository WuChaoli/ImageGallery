# 清洗 v3 第二批轻量质量算子设计

## 背景

清洗 v3 第一批算子已经覆盖图片可用性、基础尺寸、基础视觉质量、空白图和完全重复。当前开发方向正在补齐去重能力：`duplicate.perceptual_duplicate_check` 负责 pHash 视觉近重复，`duplicate.semantic_duplicate_check` 负责 image-image 语义去重。

下一批算子不应继续扩大去重复杂度，也不应直接进入 OCR、NSFW、水印、分类、检测框或审美评分等内容理解能力。更合适的方向是补齐低依赖、可解释、人工复核友好的轻量质量算子，让通用图片数据集清洗基线更加完整。

## 目标

1. 新增一批轻量图片质量与格式风险算子，继续保持 local-first。
2. 复用现有 `ImageBatch`、`ParameterComputer`、`evaluation_table` 和 `preview_html()` 能力。
3. 不引入深度模型、embedding、ANN index、OCR 或远程服务依赖。
4. 所有算子按能力命名，底层实现保持为内部参数计算细节。
5. 默认以 `review` 为主，避免轻量启发式规则造成高风险误删。

## 非目标

1. 不实现 `watermark_check`、`ocr_text_image_check`、`nsfw_check`、`face_check`、`person_check` 或 `aesthetic_score_check`。
2. 不实现 `distribution.cluster_check`、`distribution.outlier_check` 或跨数据集分布分析。
3. 不改变 pHash 去重、语义去重、export、preview 和最终 action 归并语义。
4. 不实现 bbox、mask、文本识别、分类标签或模型推理结果可视化。
5. 不在检测算子中修改、裁剪、旋转或重写图片资产。

## 算子范围与优先级

第二批按“增强质量风险识别，再补充格式和元数据风险”的顺序推进。

### P0：高价值轻量质量风险

```text
quality.exposure_check
content.border_padding_check
```

`quality.exposure_check` 用于识别明显过曝、欠曝或大面积像素截断。它比第一批的 `quality.brightness_check` 更细，因为亮度均值正常的图片也可能存在严重高光或死黑区域。

`content.border_padding_check` 用于识别大面积黑边、白边、纯色边框或截图留白。这类问题在扫描件、截图、商品图和自动导入数据集中常见，且适合通过 HTML 预览人工确认。

### P1：低信息量与噪声风险

```text
quality.noise_check
content.mono_color_check
```

`quality.noise_check` 用于识别明显噪声、低质夜景、压缩噪点或扫描噪点。第一版采用轻量统计特征，不引入模型。

`content.mono_color_check` 用于识别几乎单色、低信息量或占位类图片。它比 `content.blank_image_check` 更宽松，不只覆盖极端空白图。

### P2：格式与方向风险

```text
format.animated_image_check
metadata.orientation_check
```

`format.animated_image_check` 用于标记 GIF、WebP、APNG 等多帧图片。第一版只做风险标记，不展开帧、不抽帧、不删除。

`metadata.orientation_check` 用于标记 EXIF orientation 或显示方向风险。第一版不旋转图片，只把方向风险暴露给清洗结果和预览。

## ParameterComputer 设计

第二批新增或扩展 3 个计算单元。

### image_quality_detail_computer

阶段：`image_batch`

输入：

```text
decoded_image
grayscale_image
```

产出：

```text
dark_pixel_ratio
bright_pixel_ratio
clipped_pixel_ratio
noise_score
mono_color_score
```

服务：

```text
quality.exposure_check
quality.noise_check
content.mono_color_check
```

初始语义：

1. `dark_pixel_ratio`：灰度值低于暗部阈值的像素占比。
2. `bright_pixel_ratio`：灰度值高于亮部阈值的像素占比。
3. `clipped_pixel_ratio`：接近 0 或 255 的像素占比，用于发现死黑或过曝截断。
4. `noise_score`：轻量高频残差或局部方差指标，越高表示噪声风险越高。
5. `mono_color_score`：颜色集中度或低信息量置信度，范围 0 到 1，越高越像单色图。

该计算单元可以复用第一批 `image_quality_computer` 的灰度转换思路，但不要求合并实现。实现阶段可根据代码复杂度决定是扩展现有计算单元，还是新增独立计算单元。

### image_border_computer

阶段：`image_batch`

输入：

```text
decoded_image
```

产出：

```text
border_padding_ratio
border_padding_sides
border_padding_color
```

服务：

```text
content.border_padding_check
```

初始语义：

1. `border_padding_ratio`：疑似边框或留白区域占整图面积比例。
2. `border_padding_sides`：命中的边，例如 `top,left,right`。
3. `border_padding_color`：边框主色的粗略类别，例如 `white`、`black`、`solid`、`unknown`。

第一版只检测图片四周连续区域，不做主体分割或复杂版面分析。

### image_format_detail_computer

阶段：`image_batch`

输入：

```text
decoded_image
raw_bytes
```

产出：

```text
frame_count
animated
exif_orientation
orientation_risk
```

服务：

```text
format.animated_image_check
metadata.orientation_check
```

初始语义：

1. `frame_count`：图片帧数，无法读取时为空。
2. `animated`：是否为多帧图片。
3. `exif_orientation`：原始 EXIF orientation 值，缺失时为空。
4. `orientation_risk`：是否存在非默认方向或显示方向风险。

第一版只读取元数据，不修改图片方向。

## 逻辑算子契约

### quality.exposure_check

```text
required_parameters:
  - dark_pixel_ratio
  - bright_pixel_ratio
  - clipped_pixel_ratio
evaluation_columns:
  - dark_pixel_ratio
  - bright_pixel_ratio
  - clipped_pixel_ratio
  - exposure_action
  - exposure_reason
default_config:
  max_dark_pixel_ratio: 0.95
  max_bright_pixel_ratio: 0.95
  max_clipped_pixel_ratio: 0.98
  action: review
```

命中任一比例阈值时触发 action。reason 应说明是 `dark`、`bright` 还是 `clipped` 命中。

### quality.noise_check

```text
required_parameters:
  - noise_score
evaluation_columns:
  - noise_score
  - noise_action
  - noise_reason
default_config:
  max_score: 0.75
  action: review
```

`noise_score` 高于阈值时触发 action。第一版阈值应通过合成测试图片和少量真实样本校准，避免默认过度触发。

### content.mono_color_check

```text
required_parameters:
  - mono_color_score
evaluation_columns:
  - mono_color_score
  - mono_color_action
  - mono_color_reason
default_config:
  threshold: 0.98
  action: review
```

`mono_color_score` 高于阈值时触发 action。它不替代 `content.blank_image_check`，而是作为更宽松的低信息量风险检查。

### content.border_padding_check

```text
required_parameters:
  - border_padding_ratio
  - border_padding_sides
  - border_padding_color
evaluation_columns:
  - border_padding_ratio
  - border_padding_sides
  - border_padding_color
  - border_padding_action
  - border_padding_reason
default_config:
  max_ratio: 0.25
  min_side_ratio: 0.08
  colors:
    - white
    - black
    - solid
  action: review
```

边框或留白面积比例超过阈值时触发 action。`colors` 用于控制哪些粗略边框颜色参与判断。

### format.animated_image_check

```text
required_parameters:
  - frame_count
  - animated
evaluation_columns:
  - frame_count
  - animated
  - animated_action
  - animated_reason
default_config:
  action: review
```

`animated=True` 时触发 action。第一版不支持按帧导出，也不改变 `image_uri`。

### metadata.orientation_check

```text
required_parameters:
  - exif_orientation
  - orientation_risk
evaluation_columns:
  - exif_orientation
  - orientation_risk
  - orientation_action
  - orientation_reason
default_config:
  action: review
```

`orientation_risk=True` 时触发 action。第一版只暴露风险，不自动旋转。

## 默认配置建议

第二批算子不建议全部默认进入常规清洗配置。推荐分成两个 helper 配置：

```text
get_cleaning_v3_quality_baseline_operator_configs()
get_cleaning_v3_light_risk_operator_configs()
```

其中 baseline 可包含：

```text
quality.exposure_check
content.border_padding_check
content.mono_color_check
```

light risk 可包含全部第二批算子，用于 Notebook 人工探索和预览。

## 预览与人工复核

第二批算子应通过通用 `preview_html()` 验证，不实现专属 renderer。

推荐预览方式：

```python
cleaner.preview_html(
    "datasets/tests/operators_light_quality/preview.html",
    action="review",
    sort_by=["border_padding_ratio", "clipped_pixel_ratio"],
    ascending=[False, False],
    columns_per_row=6,
)
```

HTML 预览应能帮助人工判断阈值是否过严，而不是让算子自己承担复杂解释 UI。

## 测试策略

1. 单元测试各 `ParameterComputer`：
   - 合成过暗、过亮、截断、单色、带边框、多帧和 EXIF orientation 样本。
   - 图片读取失败时输出空参数，不中断整批计算。
2. 单元测试各 evaluator：
   - 阈值命中时输出配置 action。
   - 未命中时输出 `keep`。
   - reason 包含命中的关键参数。
3. registry 测试：
   - 默认 registry 包含第二批算子。
   - planner 能根据 required parameters 展开到对应 computer。
4. 集成测试：
   - 使用小型本地测试数据集跑 `BasicCleaner`。
   - 验证 `parameter_table`、`evaluation_table` 和 `final_action`。
   - 验证 `preview_html()` 可以生成 review 视图。
5. Notebook 验证：
   - 新增或复用轻量测试 Notebook。
   - 优先使用合成样本保证可重复，再用 `sample_1000` 做观察型验证。

## 成功标准

1. 6 个逻辑算子可以通过 `BasicCleaner([{operator_name: config}, ...])` 运行。
2. 对应参数列写入 `parameter_table.parquet`。
3. 对应 evaluation 列写入 `evaluation_table.parquet`。
4. 默认 action 以 `review` 为主，避免轻量启发式规则直接大规模 `drop`。
5. `preview_html()` 可以直接观察第二批算子命中的样本。
6. 相关 pytest、ruff 和 mypy 检查通过。

## 后续扩展

后续如果需要更强内容理解能力，应另开“内容理解算子批次”设计，单独讨论模型依赖、可选安装、缓存、推理设备、误判风险和预览形态。候选方向包括 OCR 文本图、水印、NSFW、人脸/人物、主体检测、审美评分、聚类和离群点分析。
